成交回報

ExecutionReport (8) 是 Bybit FIX API 的核心回應訊息，具有三種不同用途：

用途觸發條件ExecType
委託確認（Order ACK）NewOrderSingle (D) 的直接回應0（New）或 8（Rejected）
成交通知委託成交（部分或全部）F（Trade）
委託狀態推播被動委託狀態變更4、5 等

用途 2 與 3 僅在 ResponseMode=1（Everything）時推送。參見 ResponseMode。

這些欄位描述整體委託狀態，在每條 ExecutionReport 中均包含。

成交明細群組（NoFills）​

僅在 ExecType=F（Trade）時存在，群組中每一條目代表一次個別成交。

NoFills (30050) 為 NumInGroup 類型，宣告後續成交條目的數量。

重複組（Repeating Group）解析規則
  • Delimiter Tag：30051 FillExecID —— NoFills 組內每個成交條目必須以此 tag 開頭。解析器看到新的 30051 即代表下一條 entry 的開始。
  • 欄位順序：條目內欄位必須按下表宣告順序出現。選填欄位可省略，但存在時位置固定。FIX 引擎（QuickFIX / Onix 等）對順序敏感，錯序將直接 parse error。
Tag欄位說明
30051FillExecID執行 ID（execId）— delimiter tag，每條 entry 以此欄位開頭
30052FillQty本次成交數量
30053FillPx成交價格
30054FillTime成交時間
30055FillCommission手續費金額
30056FillCommCurr手續費幣別
30059FillCommRate手續費率
30057FillValue成交金額
30058FillIsMakerY 表示此次成交為掛單方
30063FillExecTypeTrade 或 BlockTrade
30064FillLeavesQty本次成交後的剩餘數量
30065FillSeq用於跨訊息排序的跨序列號
30066FillBlockTradeId大宗交易 ID（如適用）

當一筆委託同時產生多次成交（如掃過多個價位）時，ExecutionReport 包含單條訊息且 NoFills > 1。委託層級的 CumQty (14) 與 AvgPx (6) 反映群組內所有成交完成後的聚合狀態。

多筆成交報文示意（NoFills=2）：

...30050=2|
30051=fill_A|30052=0.001|30053=50000|30054=20260101-00:00:00.000|...|
30051=fill_B|30052=0.002|30053=50001|30054=20260101-00:00:00.001|...

每次遇到 30051 即進入下一條 entry；重複組結束後即回到 order-level 欄位（或下一個重複組）。

累計手續費群組（NoFeeDetails）​

選填，提供委託層級按幣別的手續費彙總。

NoFeeDetails (30060) 為 NumInGroup 類型，宣告後續手續費條目的數量。

  • Delimiter Tag：30061 FeeCoin —— 每個條目必須以此 tag 開頭。
  • 條目內欄位固定為 30061 → 30062；此組僅兩個欄位，均為必填。
Tag欄位說明
30061FeeCoin手續費幣別 — delimiter tag，每條 entry 以此欄位開頭
30062Fee以此幣別計算的總手續費金額

ExecType 值​

值名稱說明
0New委託已接受並在掛單簿等待
4Canceled委託已取消
5Replaced改單事件。改單受理後由此類型的 ExecutionReport 推送最終訂單狀態；OrdStatus 仍為 0（New）——UTA 的 OrdStatus 不包含 Replaced 值
6PendingCancel取消中。不會透過 ExecutionReport 推送——取消請求由 OrderCancelAck (XCA) 確認收到。
8Rejected委託或請求被拒絕
APendingNew新委託的過渡狀態。OnlyAcks 模式下，NewOrderSingle 一定會先返回 PendingNew，再返回最終的 New 或 Rejected。Everything 模式下，PendingNew 與 New 均會推送，但可能亂序到達。
DDeactivated條件委託已停用
EPendingReplace修改中。不會透過 ExecutionReport 推送——修改請求由 OrderAmendAck (XAA) 確認收到；修改後的訂單狀態由 ExecType=5（Replaced）的 ExecutionReport 推送給出（該推送中 OrdStatus 仍為 0 New，UTA 的 OrdStatus 不包含 Replaced 值）
FTrade委託成交（部分或全部）
TTriggered條件委託已觸發
UUntriggered條件委託等待觸發

OrdStatus 值​

值名稱說明
0New有效，未成交
1PartiallyFilled部分成交，仍有效
2Filled全部成交
4Canceled已取消
6PendingCancel取消請求處理中
8Rejected已拒絕
APendingNew委託提交處理中
DDeactivated條件委託已停用
EPendingReplace修改請求處理中
FPartiallyFilledCanceled部分成交後取消
TTriggered條件委託已觸發
UUntriggered條件委託等待觸發
