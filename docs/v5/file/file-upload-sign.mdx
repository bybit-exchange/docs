Get the S3 pre-signed upload URL and `resourceId`. This is **step 1** of the three-step file upload flow. **Up to 10 requests per second**

:::info Three-step file upload flow
1. **Get upload sign** (this endpoint) → obtain `resourceId` and the S3 pre-signed `urlSign`
2. **PUT upload to S3** → PUT the file directly to S3 using the returned `urlSign`
3. [**Report upload complete**](./report-file-upload) → notify the server that the upload finished
:::

### HTTP Request
<APIEndpoint method="POST" url="/v5/file/get-file-upload-sign" />

### Request Parameters
| Parameter | Required | Type | Comments|
|:----- |:-------|:-----|------ |
|[fileType](../enum#tm-onchain-filetype) |**true** |string |File business type: `fiat-pdf`, `fiat-image`, `fiat-video` |
|fileMd5 |**true** |string |Base64-encoded MD5 of the file content. Formula: `base64(md5(file_content))`, MD5 is **raw binary (16 bytes), not hex**.<br/>Golden cases for self-verification:<ul><li>Empty string `""` → `1B2M2Y8AsgTpgAmY7PhCfg==`</li><li>`"abc"` (3 bytes) → `kAFQmDzST7DWlj99KOF/cg==`</li></ul> |
|fileLen |**true** |integer |Current file size in bytes. Upper limit: `fiat-pdf` / `fiat-image` / `fiat-video` all `104857600` (100 MB) |
|fileName |**true** |string |Full file name, e.g. `evidence.pdf`, `screenshot.png`, `video.mp4` |
|fileMimeType |**true** |string |File `Content-Type`.<ul><li>`fiat-pdf`: `application/pdf`</li><li>`fiat-image`: `image/jpeg`, `image/png`, `image/jpg`</li><li>`fiat-video`: `video/mp4`, `video/quicktime`, `video/3gpp`, `video/x-msvideo`, `video/avi`, `video/rm`, `video/rmvb`, `video/wmv`</li></ul> |

### Response Parameters
| Parameter | Type | Comments|
|:----- |:-----|----- |
|resourceId |string |Resource ID, used later in `report-file-upload` and as `resources[].resourceId` in [Commit Appeal](../tm-onchain/appeal-commit) |
|urlSign |string |S3 pre-signed upload URL. Use with PUT in step 2. Valid for **30 minutes** (URL contains `X-Amz-Expires=1800`); call this endpoint again after expiry |

### Step 2: PUT upload to S3

After receiving `urlSign`, use HTTP `PUT` to upload the file content to that URL. **Note: this step does not go through the Bybit gateway — it PUTs directly to S3, no `X-BAPI-*` headers required.**

Required request headers:

| Header | Value |
|--------|-------|
| `Content-Type` | **Must exactly match Step 1's `fileMimeType`** (case, parameters — nothing may differ) |
| `Content-MD5` | **Must exactly match Step 1's `fileMd5`** (`base64(md5(file_content))`) |
| `x-amz-acl` | **Must be `private`**|


```javascript

const uploadRes = await fetch(urlSign, {
    method: 'PUT',
    headers: {
        'Content-Type': fileMimeType,
        'Content-MD5': fileMd5,
        'x-amz-acl': 'private',
    },
    body: file,
});

if (!uploadRes.ok) {
    throw new Error('S3 upload failed: ' + uploadRes.status);
}
```

Helper: compute `base64(md5(file_content))` in the browser using `crypto-js`:

```javascript
import CryptoJS from 'crypto-js';

async function computeFileMd5(file) {
    const buffer = await file.arrayBuffer();
    const wordArray = CryptoJS.lib.WordArray.create(buffer);
    return CryptoJS.MD5(wordArray).toString(CryptoJS.enc.Base64);
}
```
