:::info important
- Bybit 使用 `AtomicReplaceRequest (XAR)` 進行委託修改。不支援 FIX 標準的 `OrderCancelReplaceRequest (G)`。
- 提供 `OrderID (37)` 或 `ClOrdID (11)` 其中之一來識別委託單。若兩者均提供且不一致，以 `OrderID` 為準。
- 僅包含需要修改的欄位，未填寫的欄位保持原值。
- 僅可修改**未成交**或**部分成交**的委託單。
- **隊列優先級：** 將價格改往更靠近盤口的方向可提高隊列優先級；增加 `OrderQty` 會失去當前隊列位置；減少 `OrderQty` 不影響撮合優先級。
:::

### 訊息類型

`AtomicReplaceRequest` — MsgType `XAR`

### 請求欄位

| Tag | 欄位 | 必填 | 類型 | 說明 |
|-----|-------|----------|------|-------------|
| 30006 | ReqId | N | String | 請求 ID，用戶端自定義；若攜帶，響應會原樣回傳，便於請求/響應對應 |
| 30010 | Category | **Y** | String | 產品類型，目前僅支援 `spot` |
| 55 | Symbol | **Y** | String | 交易對名稱，例如 `BTCUSDT`|
| 37 | OrderID | N | String | 伺服器委託單 ID，`OrderID` 或 `ClOrdID` 至少填一個 |
| 11 | ClOrdID | N | String | 用戶端委託單 ID，`OrderID` 或 `ClOrdID` 至少填一個 |
| 38 | OrderQty | N | Qty | 新的委託數量 |
| 44 | Price | N | Price | 新的委託價格 |
| 99 | StopPx | N | Price | 條件委託的新觸發價格 |
| 30026 | TakeProfitPrice | N | Price | 新的止盈觸發價格，當傳"0"時, 表示取消當前訂單上設置的止盈 |
| 30027 | StopLossPrice | N | Price | 新的止損觸發價格，當傳"0"時, 表示取消當前訂單上設置的止損|
| 30030 | TpLimitPrice | N | Price | 新的止盈限價 |
| 30031 | SlLimitPrice | N | Price | 新的止損限價 |

### 回應

伺服器回應 **`OrderAmendAck (XAA)`**：

| Tag | 欄位 | 必填 | 說明 |
|-----|-------|----------|-------------|
| 30006 | ReqId | N | 若請求攜帶，響應原樣回傳；未攜帶則不返回 |
| 37 | OrderID | N | 伺服器委託單 ID。**拒絕時不返回** |
| 11 | ClOrdID | N | 原始訂單的 ClOrdID（`orderLinkId`）。**拒絕時不返回**，需依照發送順序關聯請求與拒絕回應 |
| 150 | ExecType | N | 受理成功時為 `E`（PendingReplace）。**拒絕時不返回** —— 收到 XAA 但缺少 `150/39`、且帶有 `103/58`，即代表本次改單被拒 |
| 39 | OrdStatus | N | 受理成功時為 `E`（PendingReplace）。**拒絕時不返回** |
| 103 | OrdRejReason | N | Bybit 內部錯誤碼（例如 `10001`）。僅在拒絕時存在 |
| 58 | Text | N | 可讀的拒絕說明。僅在拒絕時存在 |

:::info
`OrderAmendAck` 僅為**受理確認**（`ExecType=E` PendingReplace），僅包含最小狀態欄位，不返回完整委託資訊（數量、價格等）。最終修改狀態由後續 `ExecutionReport (35=8)` 推送給出（在 `ResponseMode=1` 模式下），或可透過 REST API 查詢。
:::

### 請求範例

```
8=FIX.4.4|9=120|35=XAR|49=CLIENT|56=BYBIT|34=3|52=20240101-08:01:00.000|
30002=1704096060000|30001=5000|
30010=spot|55=BTCUSDT|37=1234567890123456|44=51000.00|10=xxx|
```

_注意：`|` 在實際傳輸格式中代表 SOH（0x01）字元。_

### PendingReplace Ack（ExecType=E）

`ExecType=E`（PendingReplace）與 `OrdStatus=E`（PendingReplace）代表伺服器已收到並排隊處理改單，尚未進入終態。

- `OnlyAcks` 模式下這是唯一的回應。
- `Everything` 模式下這條先到，隨後會推送 `ExecutionReport (35=8)` 攜帶修改後的訂單狀態。
- 速率限制標頭（`30005` TraceId、`30007` BapiLimit、`30008` BapiLimitStatus、`30009` BapiLimitResetTimestamp）僅出現在這條 ack 上，後續狀態推播不再攜帶。

```
8=FIX.4.4|9=221|35=XAA|34=2|49=BYBIT_FIX_SERVER|52=20260820-03:27:23.303|56=FIX_CLIENT|
30005=2ee970aa6c710778146861bdcbf27553|30007=10|30008=9|30009=1787196443302|
11=aeb12cf2-d583-4c2f-9263-564d4fd18e5a|37=2285563603279252224|150=E|39=E|10=251|
```

### 失敗回應範例（已拒絕）

客戶端需依發送順序關聯本次改單請求，並透過 `103` 內部錯誤碼與 `58` 錯誤描述判斷失敗原因。

```
8=FIX.4.4|9=239|35=XAA|34=2|49=BYBIT_FIX_SERVER|52=20260820-03:47:07.284|56=FIX_CLIENT|
30005=43a6c52966d9c0f137d9fedf7e8c12a0|30007=10|30008=9|30009=1787197627283|
58=The order remains unchanged as the parameters entered match the existing ones.|103=10001|10=085|
```
